# Сборка и запуск

## Локально

Нужны Python 3.12 через `uv`, Node и `pnpm`. Локальная база поднимается встроенным PostgreSQL из пакета `pgserver`, отдельный сервер не нужен.

```bash
make devdb          # поднять встроенную базу и напечатать DATABASE_URL
make initdb         # схема
make seed           # демо-данные: около 450 синтетических кандидатов и демо-компания
make api            # бэкенд на :8000
make worker         # фоновые задачи: письма, напоминания, вебхуки
make web            # фронтенд на :5173
```

Проверки:

```bash
make test           # тесты бэкенда и фронтенда
make lint           # ruff
make bank-check     # проверка всех семейств банка
make validate       # лаборатория, полный отчёт в reports/validation.json
make openapi        # экспорт openapi.json в docs/api
make docs           # сборка документов и генерируемых частей
```

## Windows (проверка на обычном компьютере)

Нужен только Docker Desktop. Запустите `start.cmd` в корне репозитория: скрипт сам создаёт `.env` и генерирует секрет, собирает и поднимает стенд, дожидается готовности сервисов и открывает http://localhost:8080. Остановить — `stop.cmd` (данные сохраняются в томе). Первый запуск занимает несколько минут: образы, миграции, банк заданий, засев.

Нативно под Windows решение не запускается: бэкенд использует Unix-модуль `resource` и C-расширение `quickjs`, а `make` рассчитан на bash. Для Windows штатный путь — Docker, тот же, что и на сервере. Docker Desktop требует включённого WSL 2, установщик предложит его сам.

## Через Докер

```bash
make up             # локальный стенд, наружу порт 8080
make down           # остановить
make smoke URL=http://localhost:8080
```

## Развёртывание на сервере

- **Свой домен и HTTPS.** `sudo bash deploy/bootstrap.sh`. Скрипт ставит Докер, генерирует пароль базы и секрет сессий, собирает и запускает стенд, проверяет его смоук-тестом. Подробности — в `deploy/README.md`.
- **Сервер уже занят другими приложениями.** Тот же стек запускается за вашим прокси хоста: наружу открывается только `127.0.0.1:APP_PORT`, порты 80 и 443 остаются за прокси. Команда и пример конфигурации nginx — в `deploy/README.md`, разбор безопасности — в `docs/security.md`.

## Переменные окружения

Шаблон — в `.env.example`. Основное:

- `DATABASE_URL`, `SECRET_KEY` — подключение к базе и секрет сессий;
- `DEMO_MODE`, `MOCKS_ENABLED` — демо-персоны и встроенные моки;
- `PUBLIC_BASE_URL`, `COOKIE_SECURE` — публичный адрес и защищённая cookie;
- `LLM_PROFILE`, `LLM_BASE_URL`, `LLM_API_KEY` — модель;
- `FSP_ID_ISSUER`, `FSP_ID_CLIENT_ID`, `FSP_ID_CLIENT_SECRET`, `FSP_API_URL` — переход на реальный FSP ID.

## Требования к машине

Специальное оборудование не нужно. Контейнеры ограничены по памяти и вместе укладываются в 1,5 ГБ: база, API, worker, веб-сервер и почта. Продукт работает и без ключа модели.
