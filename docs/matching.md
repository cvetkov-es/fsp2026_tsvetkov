# Механика подбора

## Категория

Работодатель ищет по категории: направление и подтверждённый грейд. Внутри категории кандидаты ранжируются по силе подтверждённого профиля.

## Условия кандидата

- формат работы — офис / гибрид / удалёнка, можно выбрать несколько;
- город;
- домены;
- «Открыт до…» на `OPEN_WINDOW` дней;
- скрытый порог зарплаты спрашиваем после теста. К этому моменту медиана категории уже известна. Шаг можно пропустить.

## Потребность

Потребность описывает, кто нужен.

- **Ввод:** текст → LLM → структура → экран подтверждения. Форма — равноправная альтернатива.
- **Поля:**
  - специализация;
  - целевые грейды — множественный выбор;
  - стек must / nice;
  - формат, город;
  - вилка (обязательна, gross/net);
  - способ связи.
- **Навыки выводятся из стека.**

## Карта

**Карта** — сетка «специализация × грейд». Фильтры: стек, навыки, «есть подтверждённые достижения ФСП», формат.

**Просмотр ячейки без потребности:** сначала подтверждённые, потом неподтверждённые; внутри — по R. Это требование ТЗ.

## Подборка под потребность

Подборка строится блоками с видимыми заголовками. Каждый кандидат попадает ровно в один блок. Неподтверждённый никогда не встаёт выше подтверждённого.

1. **Подтверждённые кандидаты целевых грейдов.** При нескольких целевых грейдах — подблоки по грейду сверху вниз.
2. **Соседние грейды** — у кандидата подтверждён грейд на один выше или ниже целевого. Даётся обоснование.
3. **Без подтверждённого грейда**, заявившие один из целевых.
4. **«Почти подходят»** — жёсткие конфликты с указанием причины.

Внутри блока — по `score`, с тай-брейками.

**Переключателя «учитывать готовность» нет.** «Готовность» показывается бейджем с тултипом состава: «вилка в его ожиданиях, открыт до 20.10».

**Объяснение:**
- 3 строки фактов и минусов;
- бейджи «подтверждено / заявлено»;
- «Чего не хватает» и контрфакт — под раскрытием;
- для кандидата без ФСП — нейтральная формулировка.

**Работа с выдачей:**
- шортлист не зависит от фильтров;
- фильтры — чипы;
- диф «+3 / −2 (причина)»;
- при пустой выдаче — подсказка, что ослабить.

## Ранжирование

### Сила теста

`s = 0.5 + 0.5·clip((θ̂ − SE_PENALTY·SE − cut_g)/(cut_{g+1} − cut_g), −1, 1)`

Позиция после полного теста уточняется в обе стороны.

### Достижения ФСП

Очки по одной таблице:

| Событие | Очки |
|---|---|
| Победитель старта | `FSP_PTS.win` |
| Призёр (2–3 место) | `FSP_PTS.prize` |
| Финалист | `FSP_PTS.final` |
| Онлайн-отбор — одна строка на дисциплину | `FSP_PTS.online` |
| Разряд МС / КМС / I (действующий) | `FSP_PTS.rank` |
| **Командный результат** | **Каждому участнику те же очки**: вклад в командную работу не разделить (Q&A) |

`Σ = max(Σ результатов, очки разряда)`, `f = 1 − exp(−Σ / FSP_SATURATION)`.

Достижения поднимают кандидата внутри категории, но не заменяют тест.

### Сила профиля

- `R = s · (1 + FSP_WEIGHT·f) · m`
- `R̂ = R / R_MAX`, где `R_MAX = 1 · (1 + FSP_WEIGHT) · (1 + M_BOOST)`. Процентиль в категории показывается текстом.

### Балл под потребность

- **Покрытие стека** — среднее по must-have:

  | Состояние must-have | Значение |
  |---|---|
  | Подтверждено навыком или тестом | 1.0 |
  | Заявлено | `STACK_DECLARED` |
  | Отсутствует | 0 |

  Плюс `NICE_BONUS` × доля закрытых nice-to-have.
- **Стек кандидата не указан вовсе** → `stack = STACK_UNKNOWN` с пометкой. Штраф за отсутствующие must-have и жёсткий конфликт по must-have при этом не применяются.
- **Fit** = `(FIT_W_STACK·stack + FIT_W_R·R̂) · (MUST_MISSING_PENALTY, если ровно один must-have отсутствует)`.
- **Жёсткие конфликты** → блок «Почти подходят»:
  - отсутствуют ≥ 2 must-have;
  - формат: «только офис» против «только удалёнка» (гибрид совместим с обоими);
  - вилка ниже скрытого порога кандидата более чем на `HARD_SALARY_GAP`.
- **Accept — компоненты:**

  | Компонент | Значение | Когда учитывается |
  |---|---|---|
  | Вилка | 1, если max вилки ≥ порога; линейно от 1 до 0 при разрыве от 0 до `HARD_SALARY_GAP` | Если у кандидата задан порог |
  | Формат | 1 при совпадении, `FORMAT_COMPATIBLE` при совместимости через гибрид | Если формат задан в потребности |
  | Окно «Открыт до…» | 1, если открыто; `WINDOW_EXPIRED`, если истекло | Всегда |
  | Активность | 1, если за `ACTIVITY_DAYS` было значимое действие (вход, тест, навык, оценённое решение задачи, обновление профиля); иначе `ACTIVITY_NONE` | Всегда |

  - `Accept` — среднее по учитываемым компонентам.
  - Сигнал «Хочу к вам» применяется сверху как `max(Accept, SIGNAL_FLOOR_OK)`, если вилка не в конфликте; иначе `max(Accept, SIGNAL_FLOOR_LOW)` с пометкой.
- **score** = `Fit · (SCORE_BASE + (1 − SCORE_BASE)·Accept)`.
- **Тай-брейки:** θ̂ → f → дата подтверждения.
- **Веса** обоснованы экспертным ранжированием (ROC) и анализом чувствительности.

### Контрольные случаи

Их же проверяет лаборатория:

1. Сильный тест без ФСП стоит выше слабого теста с ФСП: R 0.79 против 0.61.
2. Подтверждённые 2 из 3 must-have стоят выше «заявленных» 3 из 3: 0.547 против 0.525 при R̂ = 0.55.
3. Три «ниже» дают m = 1 (нейтрально), три «соответствует» — m ≈ 1.12.
4. Кандидат после экспресс-теста и кандидат после полного теста при равном θ̂ различаются мягко.

## Объяснимость

У каждого кандидата есть строки объяснения: почему он в подборке и чем силён. По раскрытию карточки показывается сводка, чего не хватает, и контрфакт: что изменится при ослаблении условия. Числа и технологии в тексте сверяются с фактами карточки, модель не добавляет того, чего нет.

## Приглашение и квота

- **Оффер содержит:**
  - вилку от–до в ₽ с пометкой gross/net;
  - компанию и её уровень доверия;
  - описание;
  - «почему вы»;
  - следующий шаг;
  - способ связи после принятия;
  - срок ответа `INVITE_TTL`.
- **Предзаполнение.** «Почему вы» берётся из объяснения подборки, gross/net и способ связи — из потребности.
- **Офферы** можно сравнить рядом.
- **Ответы кандидата:**
  - **принять** → согласие №4 → контакты и **чат** (минимальный тред сообщений внутри контакта);
  - **отклонить** с причиной;
  - **встречное условие** — один раунд. У работодателя `COUNTER_TTL`. Исходы: «оффер v2» / «отклонено компанией» / «истекло». v2 занимает **тот же слот квоты**, правило «строго выше» к нему не применяется. Скрытый порог кандидата не меняется.
- **«Не показывать эту компанию»:** карточки на доске остаются, на новые приглашения компания получает ответ «кандидат недоступен».
- **Отзыв:** «Скрыть контакты на платформе и уведомить компанию».
- **Командное приглашение** — см. раздел «Найм команды целиком».
- **Квота** — число активных неотвеченных приглашений на потребность.
- **Жалоба** «спам / не соответствует описанию» уменьшает квоту на `COMPLAINT_QUOTA_PENALTY` на `COMPLAINT_PENALTY_DAYS`.
- **Защита скрытого порога:**
  - вилка фиксируется при отправке;
  - одно активное приглашение на пару «компания — кандидат» в рамках потребности;
  - повторное — через `REINVITE_DAYS`, а раньше — только с вилкой строго выше и не больше одного раза;
  - до выбора кандидата работодатель видит агрегат «вилка в ожиданиях у X из Y».

## Найм команды целиком

- **Поиск:** призовые команды стартов ФСП, у которых на платформе ≥ `TEAM_MIN_ON_PLATFORM` участников.
- **Индекс сыгранности** — среднее число совместных стартов на пару участников.
- **Групповое приглашение** — пакет индивидуальных офферов с `group_id`:
  - у каждого своя вилка;
  - квота тратится на каждого;
  - минимальный состав и срок (≤ `GROUP_TTL`).
- **Условное согласие:**
  - контакты не раскрывает;
  - участник может отозвать его до срока.
- **Статус «минимум набран / не набран»** видят работодатель и участники, но только если минимум меньше полного состава. Иначе итог открывается по сроку. Ответы друг друга участники не видят.
- **По сроку:** работодатель отправляет индивидуальные офферы v2 тем, кто согласился. Каждый принимает их заново.

## Задачи работодателя

- **Публикация** — с уровня L1, с лимитами длины и срока. В карточке задачи виден уровень доверия компании.
- **Проверка:** эталонный ответ — автоматически, открытый ответ — работодатель. LLM только советует.
- **Решения псевдонимны.**
  - «Пригласить автора» — обычное приглашение.
  - Жалоба «бесплатная работа».
  - Решение не считается откликом и на грейд не влияет.

## Доска найма и отзывы

- **Этапы:** первичное интервью → техническое → оффер → нанят / отказ.
- **Вопросы на этапах** (один клик, вариант «пока не могу сказать»):
  - на этапе «техническое» и в финале — «Уровень относительно ваших ожиданий от грейда X: ниже / соответствует / выше»; последний ответ в процессе перезаписывает прежние;
  - в финале — итог и причина;
  - по желанию — слабые области.
- **Напоминания** — `REMINDER_DAYS`.
- **Кандидат скрыл контакты** — карточка остаётся на доске только для чтения: история найма у компании не пропадает, новые этапы не ставятся.
- **Ответ во время спора** о голосе не теряется: он применится, если модератор оставит голос в силе (с новым окном спора).
- **Помощник к собеседованию** (L2+, `HELPER_MONTHLY`): `HELPER_QUESTIONS` вопросов из отдельного интервью-пула по подтверждённым навыкам и заявленному стеку. Окно месячного лимита — `HELPER_WINDOW`.
- **ATS:** этапы через вебхуки (мок, outbox, Standard Webhooks).

## Вакансии и отклики

- Обязательная вилка.
- Статусы откликов.
- Согласие №4 при отклике.

## Статистика собеседований и калибровка

**Голос:**
- только на этапе «техническое» или в финале;
- один голос на кандидата за `VOTE_TTL`;
- компания отдаёт не больше `VOTE_MONTHLY` голосов в месяц;
- голос вступает в силу через `VOTE_DISPUTE`;
- вес по уровню доверия.

**Множитель только повышающий.**
- `p̂ = (1 + Σ w·v)/(2 + Σ w)`, где v = 1 за «соответствует» или «выше» и 0 за «ниже».
- `m = 1 + M_BOOST·max(0, 2p̂ − 1)`. Значения m лежат в [1, 1 + `M_BOOST`].
- Оценки «ниже» никогда не опускают кандидата ниже нейтрального уровня. Они только уменьшают прибавку и блокируют бейдж.
- Объяснение называет прибавку открыто: «Подтверждён на собеседованиях (3) → выше в выдаче».
- Противовес списыванию работает так: честные кандидаты набирают подтверждения и прибавку, у списавших её нет.

**Бейдж «Подтверждён на собеседованиях (N)»** — N положительных голосов. Показывается при N ≥ `BADGE_MIN` и доле положительных ≥ `BADGE_SHARE`.

**Архив голосов** — только при смене грейда. При повторе того же грейда голоса сохраняются и гаснут по `VOTE_TTL`.
- Голос относится к категории «специализация × грейд». Смена специализации или грейда — архив навсегда, даже если кандидат вернётся к прежнему грейду.
- Архивный голос не мешает компании оценить кандидата в новой категории: правило «один голос за `VOTE_TTL`» считает только неархивные.

**`VOTES_UNLOCK` голосов «выше» от L2+** открывают тест на грейд выше.

**Мои оценки на собеседованиях** — приватный список «компания → оценка → дата».
- Уведомления приходят еженедельным дайджестом с нейтральной формулировкой: «компания X оставила оценку».
- Спор — в течение `VOTE_DISPUTE` и только по фактам: «собеседования не было», «не на этом этапе», «не та компания». Можно оставить комментарий для модератора.

**Калибровка порогов** методом контрастных групп:
- пакетно, при N ≥ `CALIB_MIN_N` на ячейку;
- с байесовским сжатием;
- с поправкой на селекцию;
- пороги версионируются, без пересчёта задним числом;
- сдвиг к медиане рынка документируется.

В MVP калибровка показывается на симуляции. Надёжность оценщика — после накопления данных.

## «Хочу к вам» и спрос

Кандидат может отметить компанию, тогда он поднимается в её подборках. Отметка действует ограниченное время и тратит квоту квартала. Обратно компания видит анонимный спрос по категории: сколько компаний искали похожих специалистов.

- **«Хочу к вам» — `SIGNALS` в квартал.** В Accept сигнал работает как правило max.
- **Лента задач работодателей.**
- **Вакансии и отклик** — с согласием №4.
- **Спрос как обратная связь:** агрегаты при ≥ `DEMAND_MIN_EMPLOYERS` работодателях, с задержкой `DEMAND_DELAY`, плюс призыв «подтвердите навык». Окно потребностей — `DEMAND_WINDOW`.
- **Медиана ожиданий** показывается при `MARKET_MIN_N` порогов в категории.

## Защита скрытого порога

Порог зарплаты кандидата работодателю не виден. Вилка приглашения обязательна, поэтому подбор не превращается в угадывание. Если вилка не покрывает ожидания, кандидат видит это и может отказаться осознанно.

## Статусы контакта, группы и голоса

- **Контакт** — одна таблица событий: отправлено → просмотрено → принято / отклонено / встречное → (оффер v2 / отклонено компанией / истекло) / истекло / отозвано. Этапы найма — отдельная ось. Чат — тред внутри контакта.
- **Групповое приглашение:** открыто → минимум набран / не набран → закрыто → v2.
- **Голос:** ожидает → действует / оспорен → аннулирован / действует; архивирован (при смене грейда); истёк.

## Как проверяется качество

Лаборатория считает подборку на синтетической популяции со скрытой истиной: nDCG@10, P@10, MRR, отложенную выборку, ablation и парные контрольные случаи, включая «сильный тест без ФСП выше слабого теста с ФСП». Итог на 3000 кандидатах: nDCG@10 = 0.66, у лучшего бейзлайна «ключевые слова стека» 0.33. Числа и разбивки — в `docs/validation.md`.
